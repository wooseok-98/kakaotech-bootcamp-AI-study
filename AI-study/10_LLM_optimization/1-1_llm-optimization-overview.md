# 1-1. LLM Optimization 개요

학습이 끝난 LLM의 **크기·추론 속도·메모리 사용량**을 제한된 자원 안에서 실용적으로 다루기 위해 압축·경량화·재학습 효율화 기법으로 개선하는 과정

> 모델을 처음부터 새로 만드는 사전훈련(Pre-training)이 아님 — 이미 학습된 모델의 능력은 유지하면서 **더 적은 메모리·더 빠른 속도로 실행되게 다듬는 것**이 핵심

---

## 왜 필요한가

LLM은 보통 수십억(B) 파라미터라 그대로 메모리에 올리면 일반 GPU 한 장으로 다루기 어려움

| 7B(70억) 모델 | 데이터 타입 | 필요 메모리 |
|---|---|---|
| FP32 (32비트) | 원본 | 약 28GB |
| INT4 (4비트) | 양자화 | 약 4GB |

> 상용 API(GPT-4o, Gemini)를 호출만 하면 최적화가 거의 불필요 — 하지만 **자체 GPU 서버 운영·노트북·모바일·엣지에서 직접 실행하는 순간부터 최적화는 필수**

---

## 핵심 3축

단일 기법이 아니라 모델을 실용적 상태로 만드는 여러 갈래 기법의 통칭

```
LLM Optimization
├── 데이터 타입 / Quantization  → 크기·속도 축소
├── PEFT (LoRA·QLoRA)        → 효율적 재학습
└── 배포 형식 (GGUF 등)         → 실행 환경 적응
```

| 축 | 목적 | 대표 기법 |
|---|---|---|
| **데이터 타입 / Quantization** | 가중치·활성값의 비트 수를 줄여 메모리·추론 시간 축소 | FP32, FP16, BF16, INT8, INT4, GPTQ, AWQ |
| **PEFT** (Parameter-Efficient Fine-Tuning) | 전체 가중치 대신 작은 어댑터만 학습해 재학습 비용 절감 | LoRA, QLoRA, Adapter Merge, Model Merging |
| **배포 형식** | 최적화된 모델을 다양한 실행 환경에서 바로 쓰도록 포맷 변환 | GGUF, Llama.cpp |

> 세 축은 분리된 기술이 아니라 조합해서 사용 — 예: **INT4 양자화**로 크기 축소 → **QLoRA**로 적은 GPU에서 재학습 → **GGUF** 변환으로 로컬 실행

---

## 사용 이유

같은 LLM을 더 작은 자원으로 더 빠르고 저렴하게 **실행·재학습·배포**할 수 있게 만들어, 실제 서비스 환경에서 운영 가능성을 확보하기 위함

- 모델이 아무리 성능이 좋아도 너무 커서 실행 불가·응답 지연·과다 비용이면 서비스에 쓰기 어려움
- 성능을 무조건 높이는 기술이 아니라, **좋은 모델을 실제로 사용 가능한 상태로 바꾸는** 기술에 가까움

---

## 사용 방법

정해진 절차를 무조건 따르는 게 아니라, **실행 환경과 목적을 먼저 확인**하고 그에 맞는 기법을 선택 적용

| 순서 | 단계 | 설명 |
|---|---|---|
| 1 | 실행 환경·목적 확인 | GPU/CPU 환경, 메모리 한계, 목표 응답 속도, 재학습 필요 여부, 배포 방식 확인 |
| 2 | 데이터 타입·메모리 구조 이해 | FP32·FP16·BF16·INT8·INT4 등 숫자 저장 방식 이해 (Quantization 선행 개념) |
| 3 | Quantization 적용 | 가중치·활성값을 낮은 비트로 표현해 모델 크기·메모리 축소 |
| 4 | PEFT로 효율적 재학습 | LoRA·QLoRA로 일부 파라미터만 학습해 재학습 비용 절감 |
| 5 | 배포 형식 변환 | 로컬·특정 추론 엔진용으로 GGUF 등 변환 (Llama.cpp 등과 실행) |
| 6 | 성능·품질 평가 | 크기·메모리·속도·품질 저하 여부 확인 — **자원 절감과 품질 유지의 균형** |

> 데이터 타입은 직접적인 최적화 단계라기보다 **Quantization 이해를 위한 기초 개념** — 시리즈는 데이터 타입 → Quantization → PEFT → 배포 형식 순서로 진행
