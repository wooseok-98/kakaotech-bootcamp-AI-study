# 🎈 클라이언트 - 서버 (Client - Server)

- **Client**: 요청하는 주체 (브라우저, 앱 등)
- **Server**: 요청을 처리하고 결과를 반환하는 주체

![클라이언트-서버 요청/응답 구조](여기에-이미지-드래그)

> `www.google.com`을 입력하면 브라우저(클라이언트)가 구글 서버에 페이지를 요청하고, 서버는 HTML을 응답으로 반환한다.

주소를 입력하고 화면이 뜨기까지는 대략 다음 순서로 진행된다.

1. **DNS 조회** — 도메인을 실제 IP 주소로 변환
2. **연결 수립** — 해당 IP·포트로 TCP 연결
3. **요청 / 응답** — 클라이언트가 HTTP 요청을 보내고 서버가 응답을 반환

___

## 📌 네트워크 기본 개념

서버와 통신하기 위한 기본 용어는 다음과 같다.

| 용어 | 설명 |
| --- | --- |
| **IP Address** | 서버의 위치를 나타내는 숫자 주소 (예: `192.168.0.1`) |
| **Domain** | IP를 사람이 읽기 쉽게 변환한 문자 주소 (예: `www.google.com`) |
| **Port** | 서버와 통신하는 입구. `0 ~ 65535`번까지 존재 |
| **Firewall** | 허용되지 않은 접근을 차단하는 보안 계층 |
| **Protocol** | 통신 규약. 웹에서는 주로 <span style="color:red">HTTP/HTTPS</span>를 사용 |

> **DNS**(Domain Name System)가 도메인을 IP로 변환하는 역할을 한다. `www.google.com`을 입력하면 DNS가 대응하는 IP를 찾아 그 서버로 연결한다.

포트는 한 서버에서 여러 서비스를 구분하는 번호다. 자주 쓰는 포트는 정해져 있다.

| 포트 | 서비스 |
| --- | --- |
| `80` | HTTP |
| `443` | HTTPS |
| `3306` | MySQL |
| `5432` | PostgreSQL |

## 📌 인증 vs 인가

인증과 인가는 비슷해 보이지만 **명확히 다른 개념**이다.

| 구분 | 설명 |
| --- | --- |
| **인증 (Authentication)** | 사용자가 <span style="color:red">누구인지</span> 확인한다 (로그인) |
| **인가 (Authorization)** | 인증된 사용자가 특정 리소스에 <span style="color:red">접근할 권한</span>이 있는지 확인한다 |

순서상 **인증이 먼저, 인가가 나중**이다. 로그인으로 신원을 확인한 뒤, 그 사용자가 해당 리소스에 접근할 수 있는지를 판단한다. 실무에서는 세션이나 <span style="color:red">JWT 토큰</span>으로 인증 상태를 유지한다.

> 인증과 인가는 응답 상태 코드로도 구분된다. **인증 실패(로그인 안 됨)는 `401 Unauthorized`**, **인가 실패(권한 없음)는 `403 Forbidden`**으로 응답한다.

## 📌 Client Side vs Server Side

코드가 **어디서 실행되는지**에 따라 클라이언트 사이드와 서버 사이드로 나뉜다. 브라우저는 **HTML·CSS·JavaScript만 해석**한다. 서버 언어(Python·Java 등)로 작성한 코드는 브라우저가 직접 읽지 못하므로, 서버에서 실행한 결과를 <span style="color:red">HTML이나 JSON 형태로 변환</span>해 응답으로 전달한다.

**Client Side** — 브라우저에서 실행된다.

| 언어 | 역할 |
| --- | --- |
| HTML | 페이지 구조 |
| CSS | 스타일·디자인 |
| JavaScript | 동적 동작 |

**Server Side** — 서버에서 실행된다.

| 언어 | 특징 |
| --- | --- |
| **Python** | 범용성 높음, AI/ML 생태계 강점 |
| Java | 대규모 시스템에 강함 |
| JavaScript (Node.js) | 실시간 통신에 강함 |
| PHP | 간단한 웹에 사용 |

## 📌 Database

데이터를 저장·조회·관리하는 시스템이다. 애플리케이션은 데이터베이스에 **직접 접근하지 않고** <span style="color:red">DBMS</span>(MySQL, PostgreSQL 등)를 통해 SQL 쿼리로 데이터를 다룬다.

데이터베이스는 크게 두 종류로 나뉜다.

| 구분 | 특징 | 예시 |
| --- | --- | --- |
| **관계형 (RDB)** | 행·열로 이루어진 테이블에 저장, SQL로 조작 | MySQL, PostgreSQL |
| **비관계형 (NoSQL)** | 문서·키값 등 유연한 구조, 대용량·확장에 유리 | MongoDB, Redis |
